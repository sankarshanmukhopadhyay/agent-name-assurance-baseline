# Security Policy

## Supported versions

Security fixes are applied to the current `main` branch and the latest supported release line identified by repository release/status metadata. Older versions should be treated as unsupported unless a maintainer explicitly states otherwise.

## Reporting a vulnerability

Do not open a public issue for an undisclosed vulnerability. Use GitHub private vulnerability reporting when available, or contact the repository maintainer through a private channel identified on the maintainer profile.

Include the affected version/revision, reproduction steps, impact, affected assurance evidence, and any known mitigation.

## Assurance and authority boundary

ANAB defines named-agent assurance requirements and evidence semantics. A security defect in this repository may invalidate or bound prior assurance evidence; remediation must preserve the distinction between identity/name assurance and action-specific authority. Repository fixes do not transfer authority to downstream evaluators or consumers.
