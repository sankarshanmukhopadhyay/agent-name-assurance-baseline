# ANAB v0.10.0 Release Notes

## Release Title

ANAB v0.10.0 - TIS v0.10 and AIS-1 v0.2 Synchronized Agent Assurance

## Summary

ANAB v0.10.0 updates the Agent Name Assurance Baseline for the current portfolio architecture. It aligns ANAB with TIS v0.10 runtime assurance artifacts and adds an experimental AIS-1 v0.2 interpretation layer for bonded agent identity.

The release is intentionally careful. AIS-1 v0.2 is useful because it exposes durable agent identity, sponsor accountability, ALA/SOA classification, parent-chain visibility, registry status, timestamp evidence, and assurance-container references. It is not treated as proof of delegated authority, runtime authorization, or message provenance.

## What Changed

- Added TIS v0.10 agent-name composition guidance.
- Updated the TIS compatibility review manifest from v0.9.0 to v0.10.0.
- Added an optional AIS-1 v0.2 profile extension schema.
- Added machine-readable AIS-1 v0.2 ALA and SOA examples.
- Added a TIS v0.10-backed enterprise agent declaration sample.
- Expanded AIS-1 relying-party guidance for `agentClass`, `parentDid`, DID resolution, registry status, `timestampServiceRef`, Assurance Container, and cascade revocation.
- Added portfolio drift review and release impact records.
- Refreshed README, docs navigation, known-good stack, roadmap, changelog, and validation tooling.

## Why It Matters

Named agents are becoming public trust surfaces. A relying party needs more than a name, a page, or a badge. It needs to know who is accountable, what evidence is current, what authority is actually granted, and what happens when status changes.

This release gives implementers a practical path:

1. use ANAB for named-agent assurance controls;
2. use TIS v0.10 artifacts for runtime evidence;
3. use AIS-1 v0.2 as bonded identity and accountability input;
4. use DCAS v0.10 to evaluate the evidence package when independent review is needed.

## Compatibility

This is an additive release. Existing ANAB declarations and evidence bundle examples remain valid.

The new AIS-1 v0.2 schema is optional. It extends evidence publication and relying-party interpretation without changing the core ANAB conformance declaration schema.

## Release Boundary

ANAB v0.10.0 does not make AIS-1 normative inside ANAB. AIS-1 remains experimental and bounded. The release records how to consume AIS-1 v0.2 evidence responsibly while preserving the separation between identity, delegation, authority, provenance, and assurance.
